# Рантайм Codkit в репозитории продукта

Codkit поставляет библиотеку `codkit/runtime/v<версия>/` — сервис фичефлагов,
хост фич, инспектор, имитатор удалённого источника и движок брендовых замен
для форка. Контракт — [PROP-015](../../../../vibevm/vibespecs/modules/codkit/PROP-015-runtime.xml),
команды — [PROP-007 §25–26](../../../../vibevm/vibespecs/modules/codkit/PROP-007-cli.xml),
нормы — пакет стандартов издания 1.0.0 ([13](13-standards.md)). Все команды
ниже — команды человека или оркестратора, как и у стандартов.

## Что это

Библиотека — параллельная система в собственном слое продукта, а не набор
заплаток: она лежит в `delta/own/codkit/` (в дереве —
`src/vs/<ownDirName>/codkit/`), написана по правилам апстрима и трогает его
только через узкий набор адаптеров. Фича продукта — каталог с флагом: класс,
который хост создаёт через DI, пока флаг включён, и удаляет, когда флаг
выключен. Состояние флага собирается из слоёв сборка → политика → удалённое
форсирование → пользователь → удалённое умолчание → декларация; результат —
observable, ключ контекста `<id>.enabled` для `when`. Холодная фича
(`hotToggle: false`) замораживается на старте и просит перезапуск.

## Три команды

1. `codkit runtime load [--dry-run] [--upgrade]` — кладёт побайтовую копию
   библиотеки в `delta/own/codkit/` и переписывает обе копии
   `LICENSE-CODKIT.md` с блоком компонентов. Повтор — `unchanged`, exit `0`.
   Правленая копия — `CK-E-RUNTIME-DRIFT` с путями, ничего не записано; новая
   версия библиотеки ставится только `--upgrade` (каталог заменяется целиком).
   В конце команда печатает три подсказки: прививку в корень композиции,
   строки для `code-import-patterns` и вызов `codkit gen feature`.
   Если `pin.tag` продукта не входит в список проверенных пинов библиотеки
   (`CODKIT_RUNTIME_VERIFIED_UPSTREAM`), команда предупреждает, но ставит.
2. `codkit runtime check` — только чтение: копия `identical` и уведомление на
   месте → exit `0`; библиотека не установлена → exit `0` с текстом
   `runtime not installed`; отличие → `CK-E-RUNTIME-DRIFT`, exit `1`.
3. `codkit gen feature <id> --title <text> [--setting] [--cold] [--holder <h>]
   [--license <spdx>] [--year <y>] [--header-style line|block]
   [--header-file <path>]` — скелет фичи: `delta/own/contrib/<name>/`
   с `common/<name>.ts`, `browser/<name>.contribution.ts` (класс с
   DI-конструктором и вызов `registerFeature`) и тестом
   `test/browser/<name>.test.ts` — тест лежит в каталоге самой фичи, поэтому
   в манифесте own объявляется один юнит `delta/own/contrib/<name>`, и он
   покрывает код вместе с тестом. Существующий файл — `CK-E-GEN-EXISTS`,
   ничего не записано; id не по форме `a.b` — `CK-E-GEN-ID`. Шапка —
   продукта: `--header-style line` (по умолчанию) даёт четыре строки `//`,
   `block` — блочный комментарий формы апстрима, чтобы собственный код стоял
   вровень с соседним. `--header-file <path>` (путь внутри patchesDir) пишет
   шапку дословно из файла продукта; файл обязан оканчиваться переводом
   строки, с полями шапки не сочетается, а `--header-style` без `--holder` и
   `--license` нечего оформлять — оба случая exit `2`, ничего не записано.
   Без флагов шапки файлы пишутся без шапки, с предупреждением: шапку Codkit
   в файлы продукта команда не ставит никогда.
   `codkit gen brand` пишет заготовку таблицы правил `delta/own/common/brand.ts`
   и печатает текст крючка для строкового фаннела апстрима.

Коммит в продукте после `runtime load`: каталог `delta/own/codkit/**`, обе
копии `LICENSE-CODKIT.md`; после `codkit load` дерево получает
`src/vs/<ownDirName>/codkit/**`, и `ci` коммитит его в свою ветку.

## Как продукт подключает библиотеку

1. Прививка: одна строка `import '../codkit/browser/featureFlags.contribution.js';`
   в корне композиции собственного слоя, после деклараций фич. Импорт
   относительный: lint апстрима отвергает абсолютные `vs/...`.
2. Слои импорта: цели `code-import-patterns` для `src/vs/<ownDirName>/codkit/~`
   по таблице из `LAYERS.md` библиотеки — это патч продукта типа `hook`
   (не больше трёх строк кода между маркерами, иначе `CK-E-HOOK-TOO-LARGE`).
   Прививки `header/header` (исключение для каталога `codkit/`) и списка
   ресурсов сборки — того же вида; их содержание задаёт стандарт
   `MI-GRAFT-SET-CONTENTS`.
3. Декларация фичи: `codkit gen feature acme.sample --title "Sample" --setting`
   и один юнит `delta/own/contrib/sample` в манифесте own продукта — код и
   тест фичи лежат под ним. Без `--setting` флаг читается только из сборки
   (`product.json`) и удалённого источника.
4. Сборка сама форсирует флаг через статическое поле `product`: такая
   настройка не регистрируется и не переопределяется ни политикой, ни
   пользователем (`NEVER-COUNT-A-BUILD-FLAG-AS-OVERRIDABLE`).

Инспектор — команда палитры *Feature Flags: Inspect* (`codkit.features.inspect`):
перечисляет фичи, слой, который решил состояние, и позволяет переключить
пользовательскую настройку или имитируемый удалённый снимок. Снимок живёт в
хранилище APPLICATION под ключом `codkit.features.remoteSnapshot` и идёт тем же
путём, что пойдёт снимок настоящего сервера, когда он появится.

Брендовые замены: `gen brand` даёт таблицу правил, `createBrandTransform(rules)`
из `common/brand/brandRules.ts` — чистое преобразование сообщения, которое
продукт цепляет к строковому фаннелу апстрима одним крючком.

## Что нельзя

- Не править `delta/own/codkit/**` и `src/vs/<ownDirName>/codkit/**`: `save`
  откажет `CK-E-DELIVERED-EDIT` и не зеркалирует ничего; `verify` и
  `runtime check` — `CK-E-RUNTIME-DRIFT`. Правка библиотеки делается в Codkit и
  приезжает `runtime load --upgrade`.
- Не заводить юнит манифеста own с корнем под `codkit/` — `CK-E-OWN-UNDER-CODKIT`.
- Не класть логику в прививку: патч типа `hook` — это строки подключения, не
  поведение (`NEVER-PUT-LOGIC-IN-A-GRAFT`).
- Не проверять версию апстрима во время работы: изменение API апстрима —
  правка адаптера в новой версии библиотеки (`NEVER-DETECT-UPSTREAM-API-AT-RUNTIME`).

## Стенд типов и тесты

Библиотека проверена компилятором апстрима на пине из
`CODKIT_RUNTIME_VERIFIED_UPSTREAM` (`common/version.ts`). Тесты `test/**`
написаны в стиле апстрима и запускаются в дереве форка его раннерами после
`codkit load`; первый запуск в продукте — часть второго прохода, а не
установки. Инвентарь (`codkit inventory`) показывает библиотеку одной записью
`CK-codkit-runtime` категории `delivered`.

## Лицензия

Каждый файл библиотеки несёт уведомление UPL-1.0; область действия задаёт
`LICENSE-CODKIT.md` путями (`delta/own/codkit/**`), блок компонентов в нём
перечисляет `runtime <версия>`. Файлы продукта — фичи, таблица бренда,
прививки — принадлежат продукту; `gen` ставит в них только ту шапку, что
передана флагами `--holder`/`--license`.

# Стандарты Codkit в репозитории продукта

Codkit поставляет пакет стандартов `org.vibevm.codkit/standards` — vibe-пакет
вида `flow` с нормами для patch set (издание 0.2.0: стандарт о минимальном
вмешательстве в форк). Контракт — [PROP-014](../../../../vibevm/vibespecs/modules/codkit/PROP-014-standards-and-licensing.xml),
команды — [PROP-007 §23–24](../../../../vibevm/vibespecs/modules/codkit/PROP-007-cli.xml).
Все три команды ниже — команды человека или оркестратора: агентская сессия над
продуктом их не запускает (они вне read-only allowlist хука).

## Четыре команды

1. `codkit standards load` — кладёт побайтовую копию пакета в
   `vibevm/vibepacks/org.vibevm.codkit/standards/v<версия>/` репозитория
   продукта и ведёт в `vibe.toml` продукта блок между `# codkit:begin standards`
   и `# codkit:end standards` с зависимостью точной версии и `link = "static"`.
   Ожидается exit `0` и строка `next: vibe install --offline`; повтор — `up to
   date`, exit `0`, ни одного изменённого байта. `--dry-run` печатает план.
   Дерево форка команде не нужно; `codkit.json` — тоже.
2. `vibe install --offline` в репозитории продукта — материализует пакет в
   `vibevm/vibedeps/org.vibevm.codkit.standards/<версия>/`, обновляет
   `vibe.lock` (`source_kind = "local"`) и загрузочную полосу. Codkit `vibe` не
   вызывает: это две команды подряд, и обе коммитятся вместе.
3. `codkit standards check` — только чтение: копия `identical`, лицензионная
   проверка копии чиста, обе копии `LICENSE-CODKIT.md` на месте и не правлены,
   блок `current`. Любая находка — exit `1` со своей строкой и hint
   `run codkit standards load`.
4. `codkit standards license` — печатает текст файла `LICENSE-CODKIT.md`,
   рекомендации, строки контракта `vibe scrape` (те, что `load` ведёт в
   контракте сам; см. ниже) и запись `[[annotations]]` для собственного
   `REUSE.toml` продукта. Корни не нужны.

Коммит в продукте после шагов 1–2: каталог копии, `LICENSE-CODKIT.md` в корне и
в `delta/own/codkit/`, `vibe.toml`, `vibevm/scrape/contract.toml` (если есть), `vibe.lock`,
`vibevm/vibedeps/org.vibevm.codkit.standards/**`, сгенерированные
`vibevm/vibespecs/boot/STATIC.*` и `INDEX.md`.

## Файл LICENSE-CODKIT.md

`load` кладёт уведомление о лицензии Codkit в два места: корень репозитория и
`delta/own/codkit/` (копию издания 2 из `delta/own/` он переносит сам и
печатает `moved`). Вторая копия — доставленный Codkit файл: следующий
`codkit load` доносит её в `src/vs/<ownDirName>/codkit/` дерева, `ci` коммитит
её в свою сгенерированную ветку; юнита в манифесте own она не требует.
Уведомление задаёт область действия путями — всё под
`vibevm/vibepacks/org.vibevm.codkit/**` (и проекцией
`vibevm/vibedeps/org.vibevm.codkit.*/**`), под `delta/own/codkit/**` и сам файл
принадлежат Codkit и лицензированы UPL-1.0, вне этих путей оно ничего не
лицензирует — и несёт блок компонентов (`codkit:begin components`), который
каждая доставляющая команда (`standards load`, `runtime load`) переписывает по
факту установленного; копия с устаревшим блоком обновляется, не отвергается
(рантайм и его команды — [14](14-runtime.md)).
Отдельный абзац разрешает копии, которые строит `vibe install` (загрузочная
полоса, проекция, преобразованные файлы). Релизная ветка, которую строит
`codkit publish`, файла не несёт — own-снимок публикации собирается без него;
руками или чужим инструментом файл в дереве форка не удаляют: дерево — это
материализация patch set, и удаление там прочтётся как работа. Копии не правят:
`load` откажет `CK-E-STANDARDS-DRIFT`; правленую копию удаляют и повторяют
`load`. Ссылки на файл — из README
продукта, из вмешательства patch set в README форка — ставит владелец продукта
сам, обдуманно; Codkit README не трогает. Для чистого экспорта репозитория
через `vibe scrape` две строки контракта — `[[classify]]` delete и
`[[assert]]` paths-absent для обоих путей — `load` вписывает в
`vibevm/scrape/contract.toml` сам, управляемым блоком между
`# codkit:begin scrape` и `# codkit:end scrape` (внутри блока не править,
своих строк с этими id и путями не заводить). Контракта ещё нет — `load` так и
скажет: выполните `vibe scrape contract init`, затем `codkit standards load`
ещё раз. Контракт по нестандартному пути (`vibe scrape --contract`) Codkit не
знает — для него строки печатает `codkit standards license`.

## До первой команды

`vibe.toml` продукта обязан существовать и содержать `[project]` — иначе exit
`2` с hint про `vibe init`: Codkit vibevm-проекты не создаёт. Файл обязан быть
UTF-8 c LF; CR даёт `CK-E-CRLF`.

## Что нельзя

- Не править установленную копию под `vibevm/vibepacks/org.vibevm.codkit/`.
  Отклонение от стандарта — decision record в собственных спеках продукта со
  ссылкой на якорь стандарта. Поверх правок `load` отказывает
  `CK-E-STANDARDS-DRIFT` и перечисляет `modified` / `extra` / `missing`;
  рецепт — перенести правки в свои спеки, удалить каталог копии, повторить
  `load`.
- Не заводить свою запись `org.vibevm.codkit/standards` в `vibe.toml` вне
  блока: `load` откажет `CK-E-CONFIG` с номером строки.
- Не редактировать внутри блока и не оставлять один маркер из двух: блок с
  одним маркером — `malformed`, `load` останавливается и просит починить
  руками; авто-починки нет.
- Не дописывать после `# codkit:end standards` ключи без собственного
  заголовка `[…]`: блок открывает таблицу зависимости, и такие ключи попадут в
  неё. `standards check` предупредит; новые таблицы добавляйте с заголовком.

## Новое издание

Новая версия Codkit несёт новую версию пакета. `codkit standards load` кладёт
каталог `v<новая>` рядом со старым, переводит блок на новую точную версию и
перечисляет старые каталоги как `otherVersions`; после `vibe install` старый
каталог удаляется рукой и коммитится вместе с обновлённым `vibe.lock`.

## Три лицензии, и ни одна не подменяет другую

- **Пакет** — `LICENSE` и `REUSE.toml` внутри каталога пакета описывают только
  пакет (UPL-1.0, та же лицензия, что у Codkit) и едут вместе с ним как часть
  побайтовой копии. Каждый файл пакета несёт заголовок или sidecar
  `<файл>.license`; `load` проверяет это до первой записи (`codkit license
  check` — та же проверка руками, exit `0` на поставляемом пакете).
- **Репозиторий продукта** — его корневой файл лицензии Codkit не читает, не
  копирует и не меняет; он никуда не уезжает.
- **Дерево форка** — файлы лицензии и notices форка и лицензионные поля
  `product.json` — апстримные файлы. Хотите другую лицензию на форке — это
  обычный артефакт дельты в patch set (config-overlay для полей `product.json`,
  resource-file или add-file патч для текстов), с владельцем, причиной и
  стражем; `REUSE.toml` для форка — тоже артефакт дельты.

`codkit standards load` печатает это примечание четырьмя строками `licence
note:` при каждом запуске. Пакет и стандарты — на английском языке;
уведомление о лицензии в каждом файле — по-английски и по-русски.
